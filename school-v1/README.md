# 東山學習冒險島：全校版初版

這是獨立新增的 `school-v1/` 入口，保留原網站與所有原有功能。

## 已完成

- 響應式 2.5D SVG 群島、四座主題島、八題示範任務、徽章護照、夜色與暫停動態。
- 班級代碼 101、102、201、202、301、302、401、402、501、502、601、602。
- Apps Script 驗證程式：只查選定分頁，同列 EIP帳號、EIP密碼相符才能登入。
- 依欄位標題讀取，不綁死欄號；使用顯示文字保留前導零。
- 短效 session、每帳號失敗嘗試限制、伺服器驗證答案、重複完成不重複加徽章。
- 遊戲進度另存私人試算表，不更改來源名單。

## 目前部署狀態

GitHub Pages 只提供公開試玩，**尚未連接真實學生驗證**。沒有上傳任何學生名單、密碼、試算表副本或資料。來源帳密須在校方 Google 帳號的後端比對。公開頁面禁止輸入真實帳密，直到進入 Apps Script 正式入口。

## 正式登入設定（教師操作）

1. 在校方帳號建立獨立 Apps Script 專案，把 `backend/Code.gs` 貼入 Code.gs。
2. 新增 HTML 檔，命名 **Index**，把 `backend/Index.html` 全部貼入。這份是完整網頁，不需另外新增 CSS 或 JS。
3. 建立另一份私人空白 Google 試算表存遊戲進度。
4. 到專案設定 → 指令碼屬性，新增：
   - `STUDENT_SHEET_ID`：原學生名單的試算表 ID。
   - `PROGRESS_SHEET_ID`：剛建立的進度試算表 ID。兩者必須不同。
   ID 是網址 `/d/` 與下一個 `/` 之間的文字。不要寫入公開 GitHub。
5. 在 Apps Script 編輯器選擇 `setupProgress_` 執行並授權。建立 Progress 表頭，原始學生名單不會被修改。
6. 來源班級表第一列需有：`班級`、`座號`、`姓名`、`學號`、`EIP帳號`、`EIP密碼`。登入實際使用後五項。學號需全校唯一、不可因升班而更改；正式上線前由教師確認重複與缺漏。帳號、密碼請維持文字格式。
7. 部署 → 新增部署 → 網頁應用程式。執行身分選校方管理者；存取範圍依校內政策，若學生不使用 Google 登入則需要允許該類訪客的設定。若網域政策禁止此方式，不要改公開來源表，應由學校管理者確認可用部署方式。
8. 使用部署後的 `/exec` 網址測試（不要使用只有編輯者能開的 `/dev`）。Google 可能要求額外授權或管理員批准。
9. 將 `/exec` 網址填入本資料夾 `config.js` 的 `loginUrl`，提交到 GitHub。公開網頁的「前往正式登入」會導向校方 Apps Script 網頁，正式驗證與遊戲在那裡執行，避免跨網域直接傳帳密的問題。
10. 先用老師建立的虛構測試學生確認：選錯班失敗、錯誤密碼失敗、正確密碼成功、完成任務後登出重登徽章保留。不要將測試或真實密碼貼入公開 issue。

更新 Apps Script 程式後，管理部署 → 編輯 → 新版本 → 部署；只按儲存不會更新既有正式版本。

## 使用說明與限制

- 試玩徽章僅存此瀏覽器，與正式帳號完全分開，不自動匯入。
- 正式 token 只留網頁記憶體，最長一小時；重新整理需重新登入。Cache 也可能提早失效，需重新登入。
- 共用電腦應登出。登入成功後畫面會顯示本人姓名、班級與座號，請勿讓前一位學生維持登入。
- 比對的是表中 EIP 帳密，不是 EIP 官方單一登入；原系統改密碼後須同步更新表。
- 原始表依使用者要求仍為既有帳密資料；本程式不複製密碼至遊戲進度或 GitHub，也不記錄密碼。試算表閱覽權應限管理者。
- 失敗次數限制是初版帳號層級的保護，Cache 可能提前淘汰，不是完整反機器人服務。全校公開使用前仍需容量、並發與濫用測試。
- 任務是公開的練習題，答案可查看；不能當作高風險考試或可兌現的獎勵驗證。
- 沒有即時多人連線、教師派任務、兌獎或真實點數串接。
- 後端已用虛構資料做邏輯測試；未連入正式學生資料實測，不宣稱正式服務已開通。
